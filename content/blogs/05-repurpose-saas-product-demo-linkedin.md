# Turn a SaaS product demo into a LinkedIn video without losing the explanation

Pick one feature, keep the context a viewer needs to understand it, and rebuild the framing, captions and pacing for the feed. A shorter social version is a different explanation, not a smaller copy of the full demo.

This guide assumes you already have an approved demo. To check that original for accuracy, see [SaaS product demo QA: check the interface, captions and sequence before publishing](02-saas-product-demo-quality-checklist.md). This article plans what changes between two versions. It is not a tutorial for specific software and makes no claim about reach.

## Pick one feature and one viewer action

Decide what the viewer should understand or do afterward: see what a setting does, or follow how one task is set up. A launch demo covers many features, so choose the one that can stand alone.

Write the takeaway as one sentence. If it combines two separate jobs, consider splitting it into two videos.

## Choose source scenes and add missing context

Pull the relevant scenes from the approved demo. Then ask what a viewer who has not seen the full demo would be missing: where this feature lives, what problem it addresses, what was set up earlier. Add a short context scene or caption if the original assumed that knowledge.

Keep the product's actions in the order the product requires. Skipping or reordering steps can make a feature look simpler, or different, than it is.

## Plan framing around the readable interface

A different frame shape means resizing, and resizing involves trade-offs. Cropping into the screen can cut off the panel the narration refers to. Fitting the whole frame with bars around it (letterboxing) can shrink text.

Decide scene by scene which part of the interface carries the explanation, and frame that part. If you use automatic reframing, review every scene, because nothing guarantees every interface element stays readable. Confirm how your editor handles resizing before you rely on a specific control. Descript's [Scene Editor documentation](https://help.descript.com/visuals/scene-editor-overview) describes adjusting a layer's size, position and crop, as one example of manual control.

This article lists no LinkedIn file types, lengths or aspect ratios because they can change. Check LinkedIn's current official Help pages before exporting.

## Recheck captions, narration and timing

Decide whether the video has to make sense with the sound off. If it does, captions must carry the explanation, not just repeat fragments of it.

Check how captions will be delivered. Descript's [subtitle documentation](https://help.descript.com/export-and-share/subtitles) separates SRT/VTT files uploaded alongside a video from captions that stay on the video. Confirm which form your destination accepts, and review an uploaded file as its own deliverable.

When you shorten scenes, re-time the narration. A cut can leave a sentence describing something no longer on screen.

**Illustrative example:** a demo walks through five features. The social version covers one, setting up a recurring report. This invented storyboard has four beats:

| Beat | What the viewer sees | Caption or narration |
|---|---|---|
| Context | The reports list, with the manual task named | Names the problem in one line |
| Product action | The setting being turned on | Names the control while it is on screen |
| Result | The confirmation the product shows | States what changed |
| Useful next step | A pointer to the full demo | Says where the longer explanation lives |

No performance or optimal duration is implied.

## Review the export and the post together

Watch the exported file at the size a feed viewer is likely to see, then read the post text alongside it. Does the post promise anything the video doesn't show? If the full explanation helps, link to it, and don't promise results.

**Next step:** create a one-feature storyboard using the four beats above, then compare each beat with the original demo's explanation.
