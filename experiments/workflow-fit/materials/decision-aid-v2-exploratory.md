# Keep your workflow or check one specific correction

**Independent prototype v2 — October 6, 2026. Revised from exploratory maker accounts, not participant feedback on the aid. Untested; not a product screen or output.** Frozen v1/v1.1 and the original EX01 protocol remain unchanged.

Use a product video you actually finished. If the recent task is not established, record that gap rather than invent a case.

| Check | Your project notes |
|---|---|
| What had to be delivered? | |
| Which stage needed work: planning, assets, assembly, motion or review? | |
| What source files and tools handled it? | |
| What worked well enough to keep? | |
| What correction occurred? None is valid | |
| What did the fix require and what consequence did it have? | |
| What remains unresolved, if anything? | |
| What must stay editable for the next correction or handoff? | |

**Keep:** the result met the task and corrections were manageable. Time spent on craft is not automatically a switching problem.

**Investigate:** one consequential task remains unresolved. Define the same source, correction, accuracy/control checks and delivery requirement for a future comparison when legitimate access is available. Keep the incumbent's useful capabilities in the rubric.

**Unknown:** the stage, consequence or required correction is unclear. Record that missing detail first. General tool interest is not evidence of a need to switch.

Generated assets, rendered media, editable projects and feedback links serve different jobs. Check which you need. Record the correction through export and approval rather than only the first cut. This sheet names no winning tool and promises no savings.
